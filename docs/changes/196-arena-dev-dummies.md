## Intent

ArenaController was the largest runtime class at 1,531 lines and owned nine responsibilities (F-047, census sweep 2026-09-17). About a fifth of it was the dev-only stress tower, tank dummy and air dummy: content that exists only behind `Stress.*` Tweakables, all off by default, so a player never meets it. CHARTER D8 S1 (Grey: modularization, simplification, cleanup) makes this a standing slot. CHG-022 had already collapsed the three spawn copies into one helper; this change moves the whole lifecycle out. The boundary is narrower than F-047 drew it: the friendly tank is a shipped Phase 1 scrap-loop feature spawned by default and tied to match events, so it stays, with the combat dummy and the arch dummy.

## What shipped

- `Assets/_Project/Scripts/Gameplay/ArenaDevDummies.cs` (new, 431 lines, same GameObject as ArenaController in Arena.unity): the 14 serialized fields of the "Stress test — rotor tower", "Tank dummy bot" and "Air dummy bot" headers, the five runtime handles, and the spawn/despawn/apply/fire/RPM methods for the three dummies plus CHG-022's SpawnDevDummy/DespawnDevDummy helper. It subscribes to `Tweakables.Changed` itself (Start/OnDestroy) and exposes `internal ApplyAll(state)` for the match-start path; ArenaController's own subscription and handler are gone. `ResolveTankDummyBlueprint` became `internal static` so the friendly tank's blueprint fallback still uses it.
- `ArenaController.cs`: 1,531 → 1,191 lines; the state-applied path calls `GetComponent<ArenaDevDummies>()?.ApplyAll(state)`; `RegisterChassis` and the player-chassis transform are `internal` for the new component; the friendly tank, combat dummy and arch dummy untouched.
- `Assets/_Project/Scenes/Arena.unity` (41-line diff): one new MonoBehaviour block carrying the 14 values the scene held on ArenaController, including the scene-authored `_stressTowerBlueprint` (Blueprint_StressRotorTower) and `_stressTowerPosition` (40, 0.5, 18), and those 14 fields gone from the ArenaController block. Written by the Editor over the bridge, not by hand (the values copied through SerializedObject before the old fields were deleted).
- `GameplayScaffolder.cs`: Build Everything wires the stress tower into ArenaDevDummies. `DevHud.cs`: the Respawn/Despawn Rotor Tower buttons target the new component.
- Tests: `ArenaDevDummiesSceneWiringTests` (EditMode; parses Arena.unity as text and asserts the new block carries the stress-tower wiring and the old block no longer does; RED on main) and `ArenaDevDummiesSpawnShapeTests` (PlayMode; loads Bootstrap → Arena the way the perf harness does, flips each `Stress.*` Tweakable on, asserts the spawned object's name, active flags, tag, layer, isStatic and its full component type list against the values captured live on main before the change, then flips it off and asserts the object is gone; child count is logged, not gated, because the instanced renderer consolidates block renderers over the first seconds, F-048). A `[UnityTearDown]` unloads Arena so later fixtures start clean.
