## METHOD LESSONS (the closed registry for ways of working, D9; promote to CHANGE-QUEUE § ENGINEERING RULES when one recurs)

1. **Read the plan's usage at the top of every wake** (`get_usage` from the Desktop session; `/status` in a tab). 2026-09-16: the weekly all-models window was at 100 % with extra usage enabled before the first wake, so everything shift 2 spent (~350k sonnet tokens of sweeps plus the foreground) was usage credits. D-001's default ("no overage") is enforceable by the loop itself; the "silent stall" LAUNCH-PROMPT warns about is visible from inside the session. Paid for 2026-09-16. AMENDED 2026-09-17: Grey answered D-001 ("it can" use usage credits), so the check stays and its consequence changes: record the windows in the tick and the budget ledger, do not end the shift; the D16d per-shift ceiling is the bound until Grey names a dollar figure.
2. **The Editor must serve MCP on 8080 before the Desktop session connects, or the first wake must reconnect it.** The session's MCP client dials UnityMCP once at session start; the preflight launched the Editor in the same second, the dial failed, and the whole shift ran bridge-down (no console or visual sweep, no MCP proof). CORRECTED 2026-09-17: the reconnect route does not exist for project servers (`reconnect_session_connector` refuses `.mcp.json` entries), so step 1c only reports; the ONLY fix is sequencing, i.e. the Editor serves 8080 before the loop's Desktop session is opened (BACKLOG 12). Paid for twice, 2026-09-16 and 2026-09-17. CAUSE 2026-09-17T17:05Z: the package's auto-start pref was off (LOOP-STATE § RIG); sequencing alone would never have worked because the launched Editor never served 8080 at all. Check the instrument's own switch before blaming the order of operations.
3. **`.vscode/settings.json` in the clone is not work.** The dotnet extension rewrites `dotnet.defaultSolution` to the clone's folder name on open, so it shows as an orphan at every preflight. Reverted and `git update-index --skip-worktree` set in the clone (rig config, not a commit). Paid for 2026-09-16.
8. **The test rig keeps whatever the last sync copied in, including throwaway files.** A diagnostic dropped into the clone and deleted after one `run-tests.sh` run stayed in `.claude/worktrees/test-rig` (the sync copies untracked files and only the next run resets the worktree), so a direct `Unity.exe -runTests` on the rig compiled the stale file and every spike run died in seconds with no result. Any direct rig run starts with `git -C <rig> reset --hard <sha> && git clean -fd`; the spike script does now. Paid for 2026-09-17 (one wasted spike run).
7. **A negative proof must break what the OLD code did not check, and a build chain must stop when an edit script fails.** CHG-001 round 1: the first "negative proof" renamed `rock_01.py`, the one row the broken parser did check, so it proved nothing; and the fix script had aborted on a bad assert while the chain ran on and reported the unfixed branch as fixed. Caught by the numbers (532 tests where 533 were expected). Now: every edit step in a chain carries `|| exit 1`, the fix is verified by grep before the commit, and the negative proof removes something only the fixed code can see. Paid for 2026-09-17.
6. **A finding's locator is where the sweeper looked, not everywhere the drift is.** CHG-002 fixed tip-blocks.md at the two lines F-010 named and left a third mention of the same wrong number, so the doc contradicted itself and the red team killed it. Before closing a drift finding, grep the whole file (and docs/) for the wrong value, and re-read the diagram columns after any width change. Paid for 2026-09-17 (one extra red-team round).
5. **`/inbox` from the scribe commits on whatever branch the loop has checked out.** 2026-09-17T01:52Z: the scribe's "INBOX +3" landed on `chg/003-preset-buggy-path` (and, separately, on origin/main), so the gate's frozen sha moved. Reconcile: fast-forward main, `git branch -f <chg> <its own last commit>`; the INBOX content is on main anyway. Instrument: make `/inbox` commit to main with plumbing (`commit-tree` + `update-ref`) without touching the working tree (BACKLOG 17). Paid for 2026-09-17.
4. **A file-level sweep on sonnet/medium costs 70–105k tokens** (2026-09-16: provenance 71k, invariants 74k, best-practices 100k, doc-drift 104k). Budget four or five sweeps a shift under the D16d ceiling, not eight.

9. **Every batch test run kills the factory Editor's MCP server, and the loop can restart it by hand.** MCP for Unity stores the "server I launched" handshake (pidfile path + token) in EditorPrefs, which are per user, not per project; the rig's batch Editor (same package, same user) runs the package's quit cleanup, reads the factory Editor's handshake and terminates the factory's server (F-031, 2026-09-17T12:54Z, the first shift with the bridge up). The Editor's WebSocket client keeps retrying every 30 s, so a server started by hand is picked up within a minute: `uvx --offline --from mcpforunityserver==<package.json version> mcp-for-unity --transport http --http-url http://127.0.0.1:8080 --project-scoped-tools` (ServerCommandBuilder.TryBuildCommand), launched headless with its output to a log under .utmp/factory/; started this way it carries no handshake, so a batch quit does not find it. The durable fix is CHG-015 (run-tests.sh strips the package from the rig). Check `netstat -ano | findstr :8080` after every batch run until it lands. Paid for 2026-09-17 (one partial visual sweep, one hour of diagnosis).

10. **Build a branch with git plumbing when the working tree is shared.** The clone has one checkout and the test rig syncs it, so a fieldhand's branch, a red team's suite run and the foreground's state edits all fight for the same tree. Shift 5 built CHG-014 (two files) and CHG-012 (four files plus rows) with `read-tree` / `hash-object --path` / `update-index --cacheinfo` / `commit-tree` / `update-ref` from a temporary index, never touching the checkout: the rig kept running another gate meanwhile, and a direct rig run (`reset --hard <sha>` on the worktree, LESSONS 8) measured the branch before anyone checked it out. The checkout happens once, for the red team's `run-tests.sh`, and only then. Paid for 2026-09-17 (the alternative was a serialized afternoon).

11. **Write the shift report as dash bullets, never as prose paragraphs.** `ping.py` keeps a `- ` line whole but splits a prose line into sentences before counting against the six-bullet cap, so a five-paragraph report was refused as nine bullets; and its stdout must be UTF-8 on Windows (F-043, fixed). The shift-5 report went out on the third attempt. The form is: `- ` lines, ≤ 1,900 characters, one per landing or change to main with its docs/changes number, nothing else (Grey, 2026-09-17: Discord is purely a "what changed" list at the end of every shift; CHARTER D12 v1.4). Paid for 2026-09-17.

12. **A builder brief defines "a batch run is in progress" by the command line, not by counting Unity.exe.** The live Editor spawns AssetImportWorker helpers that are also Unity.exe, so "a second Unity.exe means a batch run, wait" cost the CHG-019 builder about twenty minutes before it read the command lines itself. The rule for briefs: a batch run is a `Unity.exe` whose command line contains `-batchmode` (PowerShell `Get-CimInstance Win32_Process`); `-projectPath <clone>` without `-batchmode` is the live Editor and its workers. Paid for 2026-09-17. AMENDED 2026-09-18 (shift 8): the live Editor's AssetImportWorker helpers ALSO carry `-batchMode` (two were alive at shift start with no test running; PowerShell `-match` is case-insensitive), so `-batchmode` is not the discriminator either. A TEST RUN is a Unity.exe whose command line contains `-runTests` (run-tests.sh:141); `perf_band.py` waits on exactly that predicate before every run.

## PREDICTIONS TO SETTLE (from the template; mark paid-for or delete)

- Human bandwidth is the binding constraint and the board's caps will bind within a week.
- The first shift will be mostly instruments (the rig proven, the soak), and that is the right shift. — Half paid 2026-09-16: the rig was proven (suite 1m28s warm, green) and nothing else was built; the shift ended on the plan cap (METHOD 1), not on the ladder.
- "Can't tell" playtest verdicts will be more common than "worse" and will mean the question was wrong more often than the change was small.
13. **Check a tool response's shape once before a loop trusts it.** The perf-band script assumed `run_tests` returned `job_id` at the top level; the server wraps it under `result.data`. The first call started a job the script did not see, the retry got `busy`, the script declared failure and released the rig lock while a harness run was live. One printed response before the loop would have cost ten seconds. Paid for 2026-09-17 (one wasted run and a re-take of the lock).
14. **A plumbing-built branch does not honour .gitignore.** `hash-object`/`update-index` will happily commit a `.utmp/` report if a builder lists it; the CHG-009 builder did. Strip such paths with `update-index --force-remove` before the gate, and say in builder briefs that only paths under Assets/, docs/ or .claude/ may be listed. Paid for 2026-09-17 (one extra commit).
15. **A killed handshake-tracked MCP server ends the Editor's bridge for the shift; only prevention works.** Shift 8 (2026-09-18): a builder's direct rig run without the strip killed the shift-6 server (F-057). The foreground hand-started a replacement on 8080 within 20 min (LESSONS 9's cure), but the Editor never attached: its log said "Server no longer running; ending orphaned session" and then "Bridge is not running", i.e. when the package sees ITS OWN server die it STOPS its bridge instead of retrying (LESSONS 9's "reconnects within a minute" held in shift 5 only because the bridge was still running when the server returned). A restart needs the auto-start handler, which runs on domain reload; this Editor has Auto Refresh OFF (`kAutoRefreshMode=0`, a per-user pref shared with Grey's Editor), so a reload needs `refresh_unity` (dead with the bridge) or Ctrl+R in a FOCUSED Editor; four focus attempts (SetForegroundWindow, AppActivate, a throwaway script + Ctrl+R) failed because a fullscreen game held focus and each attempt stole Grey's screen for seconds. Rule: never run the rig without the strip (make it unavoidable: CHG-028 `run-tests.sh --at <sha>`), start every shift on a HAND-STARTED server (no handshake, nothing can kill it: the launcher should swap one in, CHG-028b), and when the bridge dies anyway, reroute the work to the batch rig (a PlayMode test replaces a live dump) rather than fight the Editor for focus. Paid for 2026-09-18 (the bridge down from 05:25Z for the rest of the shift; one builder stalled; four focus thefts).
16. **Never edit a shell script in place while a lane may be running it, and make every rig wait two-sided.** Shift 10: a player build waited for test runs but test runs did not wait for builds (F-064), so a builder's `run-tests.sh --at` reset the rig under the B3 build (CS2001 ×2); the foreground then fixed `run-tests.sh` while that builder's bash was still reading it, and its run died with `syntax error near unexpected token ';;'` (bash reads a script as it goes). Rule: a rig predicate is `-runTests|test-rig` everywhere; a script other lanes run is replaced atomically (write a temp file, then `mv`) or edited only when no lane is on the rig. Paid for 2026-09-19 (one failed build, one builder rerun).
17. **A test must not write where the player's saves live.** The rig, the Editors and Grey's own game share one `persistentDataPath`; the PlayMode suite rewrote his real `tweakables.json` on every run for two days before a directory listing over the bridge showed the file's stamp inside a rig run (F-063 → CHG-036). Before approving a test that touches Tweakables, a library or any `persistentDataPath` file: it uses a temp dir or a suspension seam, never the real folder; builder briefs for save code say so up front. Paid for 2026-09-19.
18. **After any scribe `/inbox`, the checkout's INBOX.md is STALE, and `git add docs/loop/INBOX.md` from it deletes Grey's words.** The scribe commits onto main with plumbing (LESSONS 5), so local main moves under the checkout while the working copy keeps the old file. Shift 10: the loop marked one INBOX line handled in its stale copy and committed it (1feebf82), silently deleting six newer lines (Grey's answers to the whole board) from main; the scribe's poke caught it about half an hour later; restored verbatim from dd9372d9. Rule: before ANY edit of INBOX.md, `git fetch`, then `git diff --quiet HEAD -- docs/loop/INBOX.md || git restore --staged --worktree docs/loop/INBOX.md`, then edit; after the commit, `git show --stat HEAD -- docs/loop/INBOX.md` must show insertions only. The durable fix is tooling: an `inbox_mark.py` that edits INBOX.md from `git show HEAD:` and refuses a commit that removes a line. Paid for 2026-09-19.
19. **A question card blocks the whole foreground until the click.** Shift 11 put up D-007's one card at 18:06Z with three lanes running; Grey clicked at 20:13Z, and for those two hours two finished builders, a finished gate and the rig sat idle behind the card (the harness queues every notification until the card returns). Rule: a card goes up only right after Grey has typed (he is at the desk), or as the LAST act of a wake with every other foreground item done and state written; never mid-pipeline. Paid for 2026-09-19 (two idle hours).
20. **Do not make the live Editor compile in the call that makes it resolve packages; and a failed script line does not stop a Bash call.** After CHG-038 (a package removal) landed, `refresh_unity` with `compile: request` raced the package resolve: 171 CS2001 for the vanished sources, two import workers crashed, the bridge stayed down. ONE focus + Ctrl+R recovered it (nothing fullscreen held focus that time). Rule: after a manifest change refresh with no compile, wait for idle, then compile. Same shift: a trim script failed its assert and the `git commit` on the next line still ran, twice: every step of a multi-line call carries `|| exit 1` (LESSONS 7, paid again). And the tool layer halves doubled backslashes in a heredoc: build them with `chr(92)` or check the written bytes. Paid for 2026-09-19.
