Ink behaves like ink

One physical metaphor generates every animation decision, so screens built months apart still feel like the same notebook. Anything entering is DRAWN. Anything changing value is WET ink spreading. Anything confirmed is STAMPED. Anything leaving BLOTS away — always softer than it arrived. Nothing bounces; paper is calm. The slapstick lives in the arena, not the notebook.

The four verbs

Draw — entrances

strokes & underlines scale in from their origin · t-draw 420ms · ease-draw · used once per screen, staggered 70ms

Wet — value changes

wash width follows the value, gradient tail reads as wet edge · t-settle 260ms · ease-settle · health bars, sliders, progress

Stamp — confirmations

lands at scale 1.5 → 1 in 150ms, opacity in 80ms · seals, splats, kill-feed marks · paired with a percussion cue

Blot — exits

fade + 4–6px settle downward, ~240ms · exits are always quieter than entrances · no reverse-draw

Rules

  • Interruptible always. Hover-off mid-animation retargets from the current value — tweens are retargeted, never restarted. (CSS transitions here; retargetable tween handles in Unity.)
  • Exits are softer than enters. Blot, don't reverse-draw. Shorter duration, smaller distance.
  • No bounce, no overshoot — except the stamp, which lands from above (1.5 → 1) and stops dead.
  • Idle motion budget: one element per screen. Home spends it on the spin-arc dashes (the capybara's ear twitch is a 9-second easter egg, not a loop).
  • Motion is never the only channel. Every animated state change also lands a static cue — color, position, or a mark.
  • Reduced-motion setting collapses entrances to a single fade, freezes idle loops, keeps all state feedback.

From prototype to UGUI

Everything above is designed inside what the project already does: procedural UGUI, runtime-baked InkKit sprites, UguiPalette tokens, Averia Libre + Space Mono. The stage is 1920×1080 — every coordinate transfers 1:1 to the CanvasScaler reference. What's genuinely new is one motion kit, one button component, four sprites, and five audio cues.

New pieces (the ecosystem)

  1. Core/UiMotion.cs — the token table as constants (Tick 0.08f, Stroke 0.18f, Settle 0.26f, Draw 0.42f, Page 0.64f, Stagger 0.07f, PressScale 0.96f) plus allocation-free easing evaluators (EaseSettle, EaseDraw, EasePage). The single source of truth — no magic durations in panels, same rule as colors.
  2. Core/UiTween.cs — one driver MonoBehaviour (spawned by Bootstrap, statics reset via SubsystemRegistration) ticking a fixed-capacity struct array in unscaledDeltaTime. Channels: CanvasGroup.alpha, RectTransform anchoredPosition / localScale / localEulerZ, Image.fillAmount, Graphic.color. Retargeting a live handle re-aims from the current value — that's what makes hover-off mid-animation feel right (CSS-transition semantics). Zero per-frame allocation, INV-6 clean; struct pool, no closures.
  3. UI/InkButton.cs — pointer handlers doing press (scale 0.96 + 1px), hover wash, annotation reveal, and cue routing. Replaces the hand-rolled ColorBlock wiring in every panel — this closes ui-direction.md open question #1 (the button factory), with motion included.
  4. UI/PageWipe.cs — the ink wipe: one full-screen Image (WipeBrush sprite), translate across, swap scene behind it, continue off. API: PageWipe.To("Garage"). Replaces the hard cut from MainMenu, reused by Garage↔Arena transitions.
  5. UI/SheetTitleBlock.cs — the drafting title block, parameterized (sheet no., name). Every screen gets one; the sheet number becomes the project's screen-naming convention (01 home, 02 garage, 03 arena…).
  6. InkKit additions — StrokeMask (soft-tip bar for fillAmount draw-ins), WipeBrush (screen-height brush edge), LeaderArrow, SpinArcTile (marching-dash UV scroll). All runtime-baked like the existing nine.
  7. AudioCue additions — UiConfirm, UiToggleOn, UiToggleOff, UiSlideTick, UiSealStamp, UiPageTurn (UiHover / UiClick / UiBack already exist and are wired). Voices per the Motion tab; invariant #8 is satisfied by design, not as an afterthought.

Rollout — one kit, screen by screen

  1. Sheet 01 — Home (this proposal): kit lands here first, smallest surface, highest visibility.
  2. Settings: swap hand-wired ColorBlocks for InkButton; sliders gain wet-ink fills + ratchet ticks; toggles gain knock cues. No layout change.
  3. Garage panels (BuildHotbar, VariantConfigPanel, Lab): entrance staggers on open, stamp/blot on slot changes.
  4. HUD pass 2 (already planned in the handoff): vitals needle jump + wash catch-up is the WET verb; kill-feed splats are STAMP. The kit is the missing implementation layer for that pass.

Perf + invariants: one tween driver, struct storage, no per-frame allocation (INV-6); all UI on unscaled time; entrance tweens release their slots when done; the only steady-state work on Home is one UV scroll + the fade driver already there today. No new physics objects — perf-checker can skip; qa-verifier still gates. Every interactive ships with VFX-equivalent motion AND a cue (INV-8).
